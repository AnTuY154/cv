# Kế hoạch triển khai Portfolio - Đỗ Trọng Anh Tuấn

## 1. Mục tiêu sản phẩm

Xây một portfolio cá nhân bằng Next.js để nhà tuyển dụng hoặc khách hàng có thể nhanh chóng hiểu:

- Anh Tuấn là Software Engineer thiên về Front-end, có 5 năm kinh nghiệm theo thông tin hồ sơ đã xác nhận.
- Năng lực cốt lõi là React, Next.js, xây UI từ Figma/design system, tích hợp API, tối ưu code, review code, SEO và hỗ trợ triển khai.
- Kinh nghiệm trải rộng từ enterprise tooling, bảo hiểm, hệ thống nội bộ, quản lý file/tòa nhà, dashboard dữ liệu, thanh toán, Grafana, website builder đến dịch vụ xưởng ô tô.
- OneAuto là dự án mới nhất và phải là case study nổi bật đầu tiên.
- Người xem luôn có một hành động rõ ràng: xem dự án, tải CV, mở GitHub hoặc liên hệ.

Tiêu chí thành công: trong 30-60 giây, người xem nắm được vai trò, mức kinh nghiệm, 3 dự án nổi bật, stack chính và cách liên hệ.

## 6. Design system đã chốt

Nguồn chuẩn nằm ở `design-system/anh-tuan-portfolio/MASTER.md`; trang chủ phải đọc thêm `design-system/anh-tuan-portfolio/pages/home.md` và ưu tiên override.

### Visual language

- Light-first, editorial developer portfolio.
- Nền `#F8FAFC`, text chính `#1E293B`, primary blue `#2563EB`.
- Burnt-orange `#C2410C` chỉ cho CTA/điểm nhấn; white-on-orange đạt khoảng 5.18:1.
- Font Inter bằng `next/font/google` để tránh request CSS riêng và hỗ trợ tiếng Việt tốt.
- Glassmorphism chỉ dùng ở navigation và một bề mặt hero/proof nhỏ.
- Card nội dung dài dùng nền đặc, border rõ, shadow nhẹ.
- Lucide SVG là bộ icon duy nhất; không dùng emoji làm icon.

### Motion

- Chỉ dùng hero reveal, project-card stagger và timeline reveal.
- 180-450ms; chỉ animate `opacity` và `transform`.
- Không parallax trên mobile.
- Với `prefers-reduced-motion`, bỏ animation và render ngay trạng thái cuối.
- Ưu tiên CSS transition/Intersection Observer; chỉ thêm Motion/GSAP nếu thật sự cần choreography phức tạp.

### Responsive

- Mobile-first; kiểm thử tối thiểu 375, 768, 1024 và 1440px.
- Không có horizontal scroll.
- Dòng chữ chính giới hạn khoảng 68ch.
- Grid project: 1 cột mobile, 2 cột tablet, 3 cột desktop khi nội dung cho phép.
- Các nút quan trọng cao tối thiểu 44px.

## 7. Kiến trúc kỹ thuật Next.js

### Stack

- Next.js App Router bản stable tại thời điểm triển khai.
- TypeScript strict.
- React Server Components mặc định; chỉ thêm `use client` cho menu mobile, filter và motion cần thiết.
- Tailwind CSS v4 nếu browser target là Safari 16.4+, Chrome 111+ và Firefox 128+; nếu phải hỗ trợ browser cũ hơn thì dùng Tailwind 3.4.
- ESLint, Prettier và import aliases.
- Không cần state-management library cho V1.

### Data strategy

Portfolio là static-first. Dữ liệu nằm trong typed TypeScript objects hoặc MDX local; không fetch runtime và không dùng CMS trong V1. Các trang project được pre-render bằng `generateStaticParams`.

Định nghĩa dữ liệu tối thiểu:

```ts
type Project = {
  slug: string;
  name: string;
  period: { start: string; end: string | "present" };
  company?: string;
  client?: string;
  domain: string;
  summary: string;
  responsibilities: string[];
  technologies: string[];
  outcomes?: string[];
  featured: boolean;
  ongoing?: boolean;
  confidential?: boolean;
};
```

Không dùng `any`. Content không được nằm rải rác trực tiếp trong JSX.

### SEO và social sharing

- Dùng Metadata API, `metadataBase`, canonical URL và `generateMetadata` cho project detail.
- Tạo Open Graph image bằng file convention của Next.js.
- Tạo JSON-LD `Person` cho trang chủ và `CreativeWork`/`SoftwareApplication` phù hợp cho case study; serialize an toàn, không chèn content không tin cậy.
- Tạo `sitemap.ts`, `robots.ts`, favicon và web manifest.
- Title format: `[Project] | Anh Tuan - Software Engineer`.
- Mọi project image dùng `next/image`, có kích thước/aspect ratio được giữ chỗ để CLS < 0.1.

### Performance

- Static rendering cho toàn bộ content V1.
- Chỉ dynamic import phần animation/heavy visual thực sự cần.
- Không ship icon pack toàn bộ; import icon theo tên cụ thể.
- Dùng `next/font` và `next/image`.
- Mục tiêu Lighthouse production: Performance ≥ 95, Accessibility ≥ 95, Best Practices ≥ 95, SEO ≥ 95.
- Mục tiêu Core Web Vitals: LCP ≤ 2.5s, CLS < 0.1, INP ≤ 200ms trên profile mobile hợp lý.

## 8. Accessibility và quality gates

- WCAG 2.2 AA.
- Có skip link và đúng thứ tự heading.
- Tất cả tương tác dùng được bằng keyboard; focus ring 2px rõ ràng.
- Sticky nav không che anchor hoặc focused element; dùng `scroll-padding-top`.
- Link icon có accessible name; external link thông báo rõ khi cần.
- Contrast body text ≥ 4.5:1.
- Không truyền tải trạng thái chỉ bằng màu; badge `Current` có text.
- Ảnh chân dung có alt mô tả ngắn; ảnh trang trí dùng alt rỗng.
- Không autoplay animation; reduced-motion hoạt động.
- Kiểm thử axe hoặc equivalent, Lighthouse và keyboard thủ công.

## 9. Testing

### Automated

- Type check và ESLint không lỗi.
- Unit test validation cho project data: slug duy nhất, thời gian hợp lệ, featured project đủ summary/stack.
- Component tests cho mobile menu, project filter nếu có, download link và external links.
- Playwright smoke tests cho `/`, `/resume`, mọi `/projects/[slug]`, navigation bằng keyboard và viewport 375/768/1440.
- Axe scan không có violation nghiêm trọng.
- `next build` thành công và không có route 404 ngoài dự kiến.

### Visual QA

- Chụp screenshot toàn trang ở 375, 768, 1024 và 1440px.
- Kiểm tra text overflow, orphan heading, card có chiều cao bất thường và hover/focus không làm layout shift.
- Kiểm tra không có thông tin nhạy cảm bị xuất bản ngoài danh sách đã duyệt.
- Soát copy tiếng Anh lần cuối; tên riêng và mốc thời gian khớp source.

## 10. Thứ tự triển khai cho Luna

### Phase 0 - Read and lock constraints

1. Đọc file plan này.
2. Đọc `design-system/anh-tuan-portfolio/MASTER.md`.
3. Đọc `design-system/anh-tuan-portfolio/pages/home.md` và coi đây là override.
4. Kiểm tra thư mục hiện tại trước khi scaffold; giữ nguyên mọi file có sẵn.
5. Không bịa nội dung OneAuto hoặc metric.

Exit criteria: Luna tóm tắt đúng scope, route, content policy và design direction trước khi sửa code.

### Phase 1 - Scaffold

1. Khởi tạo Next.js App Router + TypeScript strict + Tailwind.
2. Thiết lập scripts `dev`, `build`, `lint`, `typecheck`, `test`, `test:e2e`.
3. Tạo cấu trúc thư mục và design tokens trong CSS.
4. Thiết lập Inter bằng `next/font/google`.

Exit criteria: trang rỗng build được, lint/typecheck sạch.

### Phase 2 - Content model

1. Tạo typed data cho profile, company timeline, skills và 15 project.
2. Đánh dấu project confidential/ongoing.
3. Dùng đúng dữ kiện từ plan; các field thiếu để trống hoặc không render.
4. Không publish DOB/gender/phone.

Exit criteria: content validation pass; không có copy nằm rải rác trong JSX.

### Phase 3 - Foundation UI

1. Tạo layout, max-width container, spacing, typography và color tokens.
2. Xây Button, Badge, SectionHeading, ProjectCard.
3. Hoàn thiện Header/Footer/skip link/focus system.

Exit criteria: Story-like component states có default, hover, focus-visible và disabled khi phù hợp.

### Phase 4 - Homepage

1. Hero.
2. Credibility strip.
3. Featured projects với OneAuto đầu tiên.
4. Company-grouped timeline.
5. Capability groups.
6. About và Contact.
7. Thêm motion có reduced-motion fallback.

Exit criteria: đọc tốt ở 375px và 1440px, không phụ thuộc hover để hiểu nội dung.

### Phase 5 - Project and resume pages

1. Tạo dynamic route và `generateStaticParams`.
2. Tạo metadata riêng cho từng project.
3. Tạo resume web view và download link.
4. Không tạo screenshot giả.

Exit criteria: mọi project route build tĩnh và có previous/next navigation.

### Phase 6 - SEO, performance, accessibility

1. Metadata, canonical, OG, JSON-LD, sitemap, robots, manifest.
2. Image sizing, lazy loading và bundle check.
3. Keyboard, focus, contrast và reduced-motion audit.

Exit criteria: đạt quality targets hoặc ghi rõ lý do/chênh lệch có số liệu.

### Phase 7 - Verification

1. Chạy lint, typecheck, tests và production build.
2. Chạy Playwright/Lighthouse/axe.
3. Chụp và xem trực quan các breakpoint.
4. Sửa mọi overflow, contrast issue, broken link và console error.

Exit criteria: không lỗi build/runtime/console, không accessibility violation nghiêm trọng, responsive ổn định.
